Q1. In Cube3D.cpp we call glEnable(GL_DEPTH_TEST). Remove this call, how do you explain the resulting image?

When glEnable(GL_DEPTH_TEST) is removed, the depth testing is disabled. This means OpenGL will no longer compare the depth (z-coordinate) of fragments before rendering them. Instead, it will render fragments in the order they are drawn. The resulting cube appears visually incorrect and very weird. Triangles that should be hidden behind would sometimes appear in front of the triangles that should be visible. It almost look like a rotating tesseract.

Q2. Currently, all of our examples exit when Escape is pressed. Update the code to also exit when the "Q" key is pressed. What did you need to change?

To add support for exiting when the "Q" key is pressed, I needed to add an additional condition in the event handling loop. 

if (windowEvent.type == SDL_EVENT_KEY_UP && windowEvent.key.key == SDLK_Q)
  quit = true;

Q3. In CubeLit.cpp change the shader so the light is coming from below the cube. What change did you make?

To make the light come from below the cube instead of from above, I needed to modify the light direction vector in the fragment shader.

Change made:

In the fragment shader (inside fragmentSource string), I changed the light direction from: 

const vec3 lightDir = vec3(0,1,1);

to:

const vec3 lightDir = vec3(0,-1,1);
